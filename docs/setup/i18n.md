# Internationalization

English is the only shipped language. The request configuration in `src/i18n/request.ts` resolves an authenticated user's locale first, then the `locale` cookie, then the weighted `Accept-Language` header, falling back to English. URLs do not carry locale prefixes.

To add a language, translate the keys in `messages/en.json` into a new `messages/<locale>.json` file, add its locale code to `locales` in `src/i18n/locale.ts`, and extend locale resolution tests. Use next-intl translations and formatters in server and client code; retain interpolation placeholders and test dates, numbers, accessibility labels, emails and error states. Translate the offline fallback as part of that work too. A language is not ready to ship until all user-facing copy is translated and reviewed.

Application copy, accessibility labels, errors and OTP email templates live in the catalog. Server components use `getTranslations`/`getFormatter`; client components use `useTranslations`/`useFormatter`. Shared validation and background services use the typed `message` helper in `src/i18n/messages.ts`. It currently loads English only; when adding a language, extend that helper's catalog loader as well as the request loader. Never display untrusted provider error text directly: map known errors through `errorMessage` and use a translated fallback.

Users can choose English or automatic selection at `/profile`, reached through the account menu. `PATCH /api/profile` accepts only a supported locale or null, verifies the session and request origin, persists the preference for the authenticated user, and synchronizes the locale cookie. Automatic selection clears both the saved preference and cookie.

Shared presentation formats are in `src/i18n/formats.ts`. Dates use UTC for consent records; ISO strings remain appropriate for API payloads, date/time inputs and machine-readable attributes. Format numbers with the i18n formatter; format money with `format.number(amount, { style: "currency", currency })` when a money surface is introduced. No money surface is shipped in PR 03.

`npm run lint` and unit tests run the TypeScript AST source guard in `scripts/source-guards.ts`. It rejects literal JSX text, user-facing attributes, error constructors and feedback setters throughout `src`, including shadcn components. Run `npm run generate:offline` after changing copy or tokens; the public fallback is generated from the same English catalog and shadcn Card/Button primitives. Browser coverage checks profile persistence, unsupported locales, account injection, origin checks and missing messages.
