# PWA verification

The manifest is generated by `src/app/manifest.ts`. It declares the app name, standalone display, root scope/start URL, semantic theme colors and local 192/512px PNG icons. `RegisterServiceWorker` automatically registers `/sw.js` only in production.

The worker stores exactly four public assets: `/offline.html`, `/offline.css`, and the two icons. Navigation requests use the network and fall back to the public offline page on failure. API requests, workspace HTML, session responses, uploads, tenant records and third-party requests are never added to Cache Storage. Activation removes older Harvest offline caches. Bump the worker cache version when changing fallback assets.

Run `npm run generate:offline` to regenerate the public page from shadcn Card/Button primitives, English messages and the theme registry. It contains no user or tenant data. The fallback applies saved theme preferences before paint and includes a retry link.

Run `npm run build && npm run test:pwa` with a local Chrome installation (or `CHROME_PATH` pointing to Chromium). The verification starts a local production server, opens only anonymous pages, overrides live integration configuration, and never sends email. Lighthouse 13.6 has no built-in PWA category, so the script adds an explicitly named Harvest PWA audit that uses Chromium's `Page.getAppManifest` and `Page.getInstallabilityErrors`, and verifies automatic activation of the production worker. An empty error list is required. Lighthouse accessibility must also score 100.

The same run verifies production offline navigation, exact public cache contents and axe, then writes `lighthouse.json`, `production-offline.json` and `production-offline.png` into `docs/screenshots/pr03/`. The regular Playwright suite separately visits authenticated workspace/API routes, checks no tenant responses entered the cache, and captures/axe-checks the fallback in all four themes. CI runs both suites and uploads the evidence. Localhost is a secure-context exception for development; the deployed application must use HTTPS.
