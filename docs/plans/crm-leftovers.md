# CRM leftovers requiring decisions

The [CRM roadmap](professional-v1-audit-proposal.md), [CRM PRD](../prd/PRD-v2.7-companion.md#5-crm--twenty-inspired-customer-and-relationship-management), and [founder decisions](../decisions/founder-decisions-2026-11.md) establish the feature boundaries. The items below need decisions before implementation.

| Item | Decision needed |
| --- | --- |
| CRM retention and erasure | Specify retention windows and their start events for raw CSV rows, CRM outbox events and deliveries, and CRM association payloads. Define what expiration means for import rollback and webhook retries and replay. Decide whether withdrawal erases previously recorded associations, how to handle identifiers discarded during a merge, and which task text and audit evidence may remain after erasure. Keep existing purpose-specific consent, canonical merge behavior and the erasure audit protections while those decisions are open. |
| Approval requests and human review | Specify the pending-request cap or rate limit and its scope, plus the human confirmation mechanism and the minimum server-held review data and erasure rules. The ten-minute lifetime and single-use concurrency behavior are already specified in CRM-08. |
| Pipeline conversion | Define the cohort and denominator (deals created, deals closed, or entry into a stage), treatment of reopened and archived deals, pipeline moves, and which timestamp sets the reporting period. |
| Follow-up task throughput and overdue | Define the population (CRM tasks or Connect cases), throughput events (including reopened tasks), whether overdue is a current or historical snapshot, and staff visibility (own work or ministry totals). |
| Source performance and contact growth | Define the outcome for each source, first/latest/any attribution for multi-source contacts, imported, merged and erased contact treatment, and whether growth measures additions or net change. |
| Report access and disclosure | Confirm the staff scope for every report, the ministry or caller time-zone source, available periods and breakdowns, and a suppression strategy that protects cohorts below five against subtraction across totals, overlapping periods and filters. HC-15 covers Connect campaign aggregates. Its contract is specific to those aggregates. |
| CRM notifications | Define when due and overdue events fire, what happens on rescheduling, completion, reassignment or membership changes, which CRM surfaces can create structured mentions and who can receive them, and the default and scope of each preference. CRM-05 already specifies recipient-scoped assignment notifications. Keep email and push hard-off, with any delivery verification using a fake sink. |
| Sync diagnostics | Identify the CRM sync operations and status source that support should monitor, and specify the safe status vocabulary. CRM-08 defers email/calendar sync. CRM-07 specifies consent-gated association events. CRM-06 already defines import lifecycle statuses for the import diagnostics. |

Sources for privacy and lifecycle decisions include [CRM-05](../acceptance/crm-05.md), [CRM-06](../acceptance/crm-06.md), [CRM-07](../acceptance/crm-07.md), [CRM-08](../acceptance/crm-08.md#deferred-exact-remaining-work), [CRM soft follow-ups](../superpowers/specs/2026-11-13-crm-soft-followups-design.md), [HC-14](../acceptance/hc-14.md), [HC-15](../acceptance/hc-15.md), and the [HC-02 activation register](../decisions/hc-02-activation-gates.md). All five HC-02 gates remain UNAPPROVED.
