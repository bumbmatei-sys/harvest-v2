## Zernio reuse assessment

Fresh GitHub inspection pins LateWiz at `28dd018063b955769de11f881acd03bb64c61cd4` and Unified Inbox at `3d62be18923df6fa22fa01037a2057254553206d`. Read READMEs, LICENSE, package manifests, trees and representative integration files. Both LICENSE files are MIT; retain copyright and permission notices for copied portions. Transitive dependencies and exact adapted files still require pinned license/security review before copying.

* LateWiz: Next 16/React 19/Tailwind 4/shadcn; reusable composer, account controls, calendar, queue and platform option patterns. Adds React Query, Zustand, React Hook Form and Zernio SDK absent from Harvest's current dependency set. `src/stores/auth-store.ts` persists API keys in browser state; `src/lib/late-api/client.ts` allows explicit client keys. **Do not port those credential patterns.** Adapt selected UI into existing AppShell/tokens, use server-only Harvest integration services, and choose additional dependencies only for actual consumers.
* Inbox: Next 15/React 19/Tailwind 4/shadcn/React Query; useful conversation list, thread/media rendering, filtering, composer and retry UX. README explicitly states no authentication, no database and polling (10-second list/5-second thread). `src/app/api/conversations/route.ts` accepts accountId directly and otherwise filters by cookie selection; neither establishes Harvest tenant ownership. Replace proxy authorization with server-derived tenant/account grants and resource checks for every conversation/message/action. Do not import WhatsApp calling, broadcasts or unrelated rich workflows merely because source exists.
* Integration boundary: Harvest owns provider-neutral connection, publish/schedule/status, conversation/reply and Auto-DM contracts. Persist tenant-to-provider-account bindings; normalize capability/errors; validate OAuth state, webhook authenticity/replays, revocation, quotas and retry/idempotency. Decide scheduling ownership explicitly so provider and Harvest workers cannot both publish the same post.
* Direct access to `docs.zernio.com/llms.txt` and the Instagram platform page failed with HTTP/proxy 403 in this session. Existing PRDs/Craft contain prior public-doc findings for publishing, inbox, eligible Auto-DMs and four Blogs destinations; these were reviewed but **not freshly independently verified against API documentation here**. Frontend source confirms some endpoint usage, not API-wide support. Before integration implementation, complete a dated per-platform capability matrix from accessible official docs and sandbox accounts. No live calls/posts/messages or keys were used.
* Preserve earlier five priority networks (Facebook, Instagram, Threads, TikTok, YouTube) pending a contrary decision. Five network types do not imply five connected accounts. Never promise common DM/Auto-DM support across them. Account allowances, provider costs/DPA and tenant profile model remain open.
