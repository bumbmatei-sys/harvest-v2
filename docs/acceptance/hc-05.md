PR #30, 7 November 2026. Baseline: main `b1da5a4` (HC-03). Implementation authorized by Matei after choosing pastoral follow-up and newsletter signup as separate unchecked opt-ins; invitations remain later. This acceptance record covers the bounded local synthetic implementation, not a public launch or completion of the activation policy.

## Behavior and scope

A live QR/short link can present its immutable published form/notice beside free resources. The visitor can choose follow-up, newsletter, or both; the shared email is collected once with separate subject-origin evidence. Preferred name is optional and can be omitted by the admin preset. Pending confirmation explicitly says no message was sent and no subscription activated. Resources require no identity, cookies or submission. Account invitations, CRM association and delivery remain unavailable.

Owners/admins can configure the two offered purposes, optional name, synthetic notice and explicit test retention through a small settings panel backed by canonical Forms. Only email is currently supported: the inherited consent channel contract is email/SMS, so voice/phone support needs its own reviewed change. Revisions create immutable versions. A revised form requires creating/publishing a new QR link; existing links and submitted evidence are never silently switched.

The UI uses shadcn components, translated English messages, full-width app shell and 44px controls. No arbitrary fields, sensitive categories, prayer notes, birth dates or contact-based matching are added.

## Persistence and trust boundary

Migration 0028 adds three FORCE-RLS tables with no direct `harvest_app` table grants: encrypted receipts, bounded short-lived quota/revocation keys and a restricted guest/worker event ledger. Canonical pending response/contact-method/consent records remain authoritative. Canonical contact rows contain an opaque sealed reference, not plaintext; preferred name and contact values live only in authenticated AES-256-GCM ciphertext. The stored AAD binds source, submission and receipt. A separate keyed fingerprint detects changed-body replay without creating an email lookup index. No decryption or contact-reading API is exposed.

Narrow definers derive tenant/campaign/form ownership from the authoritative code, check current publication/expiry/archive state and lock source rows before accepting a write. The public manifest contains only permitted definition/choices/notice/retention plus a version stamp, a signed 10-minute presentation capability and its private receipt token. The receipt is a one-way hash of that randomly issued capability; submission checks the binding, so an old receipt cannot be paired with a fresh proof to extend accepted retries past its suppression lifetime. It contains no tenant, campaign, response or internal form IDs. Source, version, offered purpose and required channel are rechecked atomically. No CRM contact, membership, case, generic outbox event, job or delivery is created.

Same payload + submission key + private receipt is idempotent. Changed body/proof conflicts. Submission and guest rights serialize on the receipt hash before row locks. Legacy owner/contact erasers already holding a response lock use a nonblocking receipt lock: contention aborts the entire erasure with SQLSTATE 40001 (HTTP 409), requiring retry. A successful erasure is never acknowledged while a saved POST can recreate its intent. Short-lived revocation hashes survive only until the enforced presentation proof expires; old proofs then fail before any insert. Existing coarse canonical tombstones remain subject to the unapproved linkability decision.

The browser freezes the first attempted payload for safe retries (a definite validation 400 clears it and allows correction) and renders withdrawal from that snapshot. It exposes the private recovery code after success or an uncertain error; no proof is placed in a URL, cookie, local storage or generic log. The proof authorizes only per-purpose withdrawal/erasure, never identity verification or CRM association. Unknown, expired and already-erased proofs receive the same acknowledgement. Limited requests receive 429 rather than a false applied acknowledgement.

Erasure removes ciphertext/methods, rekeys/unlinks/coarsens the restricted events and invokes the existing canonical scrub path. A bounded expiry-only definer purges at most 100 receipt-backed expired responses, without borrowing an owner identity. `npm run connect:purge:test` runs that operation as the nonprivileged app role, closes its pool and emits redacted diagnostics. It is an explicit local operator command, not a deployed schedule.

## Local operation and limits

Intake requires all of: nonproduction process, `HARVEST_CONNECT_INTAKE=synthetic`, a localhost `harvest_test` or `harvest_test_*` database and a disposable 64-hex `HARVEST_CONNECT_TEST_KEY`. Production is hard-disabled even if the flag is supplied. Only reserved `@example.test` email addresses are accepted. The Playwright server enables this mode against its disposable local DB with a random test key; normal resource-only sources still omit forms.

Example for an already provisioned disposable local database: set these variables plus existing auth settings in your local environment, run migrations through the normal migration owner, start the development app as `harvest_app`, and use campaign Connect → Configure test form → publish a test revision → create a new QR attached to that revision → publish the QR. Use only fabricated data. The purge command requires the same local mode/key/database and the actual `harvest_app` role. It cannot run against remote/production databases.

Bodies are streamed and capped at 32 KiB with strict JSON/schema/UTF-8 checks, same-origin POST checks and a honeypot. Persistent test quotas are 600/source/minute, 12/private receipt/minute and 600 guest-rights/minute. These are repeatable test bounds, not evidence of venue/load safety or an approved production abuse policy. No IP is collected or used as guest identity. Adaptive challenge, production thresholds and crowd/load testing remain activation work.
