# PR 02 — files foundation verification

Branch: `feat/pr02-files`, based on the latest `origin/main` pulled at task start.
No contacts, shell or authentication implementation changes are included.

Story: a signed-in workspace member opens Files, requests a constrained upload,
uploads bytes directly to S3-compatible storage, confirms integrity/processing,
sees the persisted file, and downloads it through a membership-checked grant.

| Boundary | Evidence |
| --- | --- |
| Workspace → Files | Existing workspace card links to the new authenticated files page. |
| Browser → API | Playwright creates the intent, uploads using the actual presigned PUT, confirms, and reloads the list. |
| API → database | Forced RLS with `USING` and `WITH CHECK`; direct cross-workspace read/insert/update/delete tests with the non-owner runtime role. |
| API → storage | Real AWS SDK adapter against a loopback S3 subset that validates SigV4 signatures, expiry, exact size/MIME headers and write-once condition. |
| Stored bytes → processing | SHA-256 is computed from actual downloaded bytes; mismatch/infected verdicts quarantine. Missing objects cannot confirm. |
| Private download | Browser saves the download and compares the exact bytes; ready private files have no public URL. |
| Public delivery | No-op public uploads quarantine. Injected clean verdicts in integration tests exercise anonymous delivery; only one ready public row is visible and anonymous writes remain denied. |
| Authorization | Viewers cannot upload; another member cannot confirm an uploader's file. No foreign-workspace/file ID reaches the signer. Browser tests use two real OTP-authenticated accounts. |
| Processing retry | Scanner failure preserves committed `uploaded` state. Repeated confirmations are idempotent. |
| UI | Desktop/mobile axe checks, no document overflow, no page errors. |
