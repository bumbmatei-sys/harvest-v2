# Newsletter sending and provider evidence

## Screen API

Owner and admin only. The base path is `/api/workspaces/[tenantId]/newsletter`. Reads and estimates return private, no-store JSON. Collections use the immutable UUID `after` cursor and a `limit` of 1–100, default 50. Mutations use the app's existing origin check. An inaccessible ministry or record returns a neutral 404. Conflicts carry a fixed code.

| Method and path | Contract |
| --- | --- |
| GET / POST `campaigns` | List drafts and dispatch state, or create a draft. Draft input includes name, subject, optional preheader, sender and reply-to IDs, selection, and exactly one of content, template ID or starter ID. |
| GET / PATCH `campaigns/:id` | Read the current revision. PATCH takes draft input and the current campaign version and creates a revision. Editing a reviewed draft requires a new review. A finalized revision is frozen. |
| POST `campaigns/:id/review` | Takes `{version, dispatch}`. Returns sender and reply-to, selection pins, estimate, HTML and plain-text preview, headers, and a one-use token with the new version and expiry. The token expires after 10 minutes. |
| POST `campaigns/:id/send` or `campaigns/:id/schedule` | Takes `{version, token, dispatch}`. Send uses `{mode:"now"}`. Schedule uses `{mode:"schedule", schedule:{at,timezone}}`, where `at` includes seconds and the local UTC offset, and `timezone` is an IANA zone. The offset distinguishes fall-back instants. Nonexistent spring-forward times are rejected. The server and database cap the scheduled time at 60 days after review. An over-limit API request returns HTTP 400 with `SCHEDULE_TOO_FAR`. |
| POST `campaigns/:id/cancel` / `duplicate` / `send-test` | Cancel takes `{version}`. Duplicate takes `{name}` and creates a fresh draft. Send-test uses the verified session user's own address transiently and a fake delivery sink. |
| GET / POST `templates` and GET / PATCH / DELETE `templates/:id` | List includes built-in starters. Create takes name and content, edit also takes version, and delete archives with `{version}`. Campaign creation copies the chosen layout. |
| POST `recipient-estimate` | Takes `{listIds, segmentIds?}`. Returns selected and eligible estimates and fixed reason counts. Segments filter lists in their own audience. Only existing list memberships enter the selection. The selection cap is 5,000 memberships across up to 20 lists and 20 segments. |
| GET / POST `sender-identities` and PATCH `sender-identities/:id` | GET includes domain DNS instructions, check status and version for sender identities, including the `dmarc` verification flag and the exact `_dmarc.<domain>` TXT record. POST takes `{address, purpose}` with `sender` as the default. PATCH accepts `{version, enabled}`, `{version, action:"request-code"}` or `{version, action:"confirm", code}`. Sender and reply-to require separate ownership challenges. An external reply-to has no sending domain record. |
| GET `campaigns/:id/delivery-status`, `analytics`, and `analytics/:id` | Reports UTC cohorts by selection day. Query parameters `from` and `until` are inclusive and exclusive UTC dates, with a maximum span of 90 days. No individual outcomes are returned. |

The preview uses the same renderer as dispatch, with a fallback name and a non-authorizing unsubscribe URL. Deliveries substitute the current approved variable values and a recipient-bound NL-02 URL. The body supports the constrained rich-text document, a verified HTTPS button, a scanned ready public image from the same ministry, a divider, spacing, and the mandatory unsubscribe footer. Revisions retain the authored subject, preheader and content and an unpersonalized text preview. Recipient-rendered messages, raw callback bodies and mailbox confirmation messages are transient. Footer and header values use the NL-02 signed token and RFC 8058 list scope. GET is read-only.

## Delivery and privacy

The worker uses its own database login and checks the frozen revision, current list and segment pins, both mailbox versions, the sender domain version, suppression and current consent. The SQL authorization boundary follows the canonical contact-then-subscriber lock order. Withdrawal, erasure, merge, cancellation, identity disablement and domain changes committed before authorization win. Submission happens after authorization commits. An already accepted message cannot be recalled.

Each ministry registers its own sender domain. DNS instructions include ownership TXT, DKIM, SPF, bounce MX and required DMARC. The suggested TXT value is `v=DMARC1; p=none`. Policies `p=quarantine` and `p=reject` also satisfy the minimum. The fake recheck simulates verification for per-ministry domains under `*.example.test`. It excludes the shared preview domain. Recheck after 24 hours and block after 48 hours without a successful current verification check. Status changes increment the domain version and invalidate old reviews. The ownership challenge is a one-time, 30-minute code delivered to each sender or reply-to separately through the synthetic sink. Reply-to supports external mailbox addresses. Harvest hosts no mailbox.

An immutable delivery UUID is passed as a message tag. An ambiguous attempt can be reconciled by an authenticated event carrying both the tag and provider message ID. Subsequent notifications must match the attached provider ID. Successful delivery, permanent bounce and complaint can arrive out of order.

The SNS verifier requires RSA-SHA256 signature version `2`, the exact configured topic ARN and a certificate pinned under the regional HTTPS SNS hostname and allowed PEM path. It accepts signed timestamps up to 24 hours old and five minutes ahead of the local clock. The callback atomically records the signed SNS envelope `MessageId` and applies the delivery event. A committed replay, malformed input or unauthenticated input receives the same empty HTTP 202. Only an authenticated, parsed event with an internal application failure receives HTTP 503 so SNS can retry. The fake callback uses an injected synthetic key. The adapter accepts injected certificate material. Subscription confirmation is an operator step. [Activation runbook](../runbooks/newsletter-activation.md)

The worker marks attempts still unknown after 48 hours as `operator_review` and records when the transition happened. Health output and alerts include each affected ministry’s oldest unresolved attempt age in seconds, with separate unknown and operator-review counts. No attempt is resubmitted. A later authenticated callback can still reconcile either state until the delivery row expires.

The analytics report counts only UTC campaign/day cohorts. It suppresses cohorts of fewer than five and any cross-campaign day or range that would expose those cohorts by subtraction. Attempt, acceptance and delivery denominators are selected, attempted and accepted respectively. Open/click tracking and inbox features are outside this slice.

Campaigns, templates and active subscribers remain as needed. The worker purges individual delivery rows when 90 days have elapsed from selection. A delivery still queued at that age expires. The purge skips an active lease until it expires. The same transaction rolls counts into anonymous campaign/day counters, including separate `unknown` and `operatorReview` totals, and records only a run time and delivery purge count. Unknown and operator-review rows are deleted on the same 90-day schedule. The worker also deletes expired callback receipts in a separate bounded batch within the transaction. It preserves totals across partial runs and omits current eligibility for a cohort once any rows have been purged. The archive contains no subscriber, address, list, delivery or provider IDs. A suppression digest is personal data. The stored fields are ministry/list scope, HMAC-SHA256 of the normalized address scoped to the ministry, a key version, a reason code and a timestamp. Active and historical peppers come from injected configuration. They are bound only for the SQL transaction and are absent from database tables, functions and persistent settings. An omitted key fails closed for ministries with suppression records under that key. Contact erasure clears the attempt digest once no canonical subscriber link remains. A new verified signup deletes matching prior unsubscribe rows for its scope across available key versions. Hard bounce and complaint rows survive contact erasure to block a recreated address. Exceptional deletion and its authorization remain pending privacy approval. [Erasure procedure](../runbooks/connect-rights-requests.md#newsletter-suppression)

The operator commands `npm run newsletter:deliver:test`, `npm run newsletter:domains:test` and `npm run newsletter:purge:test` run one bounded batch using `WORKER_DATABASE_URL`. Each requires its explicit non-production flag, respectively `HARVEST_NEWSLETTER_WORKER_ENABLED`, `HARVEST_NEWSLETTER_DOMAIN_RECHECK_ENABLED` or `HARVEST_NEWSLETTER_RETENTION_ENABLED`. Delivery uses an injected token key and suppression key ring. The synthetic callback also requires `HARVEST_NEWSLETTER_CALLBACK_ENABLED` and an injected callback key. No scheduler or live transport is installed.

| Area | Documented contract and local evidence | Unverified |

| Domain and bounce identity | SESv2 supports regional email identities, Easy DKIM and custom MAIL FROM; the latter uses SPF TXT and feedback MX. The synthetic recheck covers ownership, version changes, mandatory DMARC, and worker authorization. [Identities](https://docs.aws.amazon.com/ses/latest/APIReference-V2/API_CreateEmailIdentity.html) · [Custom MAIL FROM](https://docs.aws.amazon.com/ses/latest/dg/mail-from.html) | Hosted identity registration, real DNS values and rechecks, alignment and MAIL FROM rejection policy. |
| Sender and reply-to | SES verifies sending identities and `SendEmail` accepts reply-to addresses. Harvest independently challenges both mailboxes in the fake flow. [SendEmail](https://docs.aws.amazon.com/ses/latest/APIReference-V2/API_SendEmail.html) | Real delivery of Harvest’s ownership confirmations and replies to external inboxes. |
| Lost receipt and event shape | `SendEmail` returns `MessageId` and accepts a configuration set and `EmailTags`. Event publishing includes `mail.messageId` and `mail.tags`. Local tests reconcile a distinct provider ID by delivery tag and reject a mismatching ID. [SendEmail](https://docs.aws.amazon.com/ses/latest/APIReference-V2/API_SendEmail.html) · [SES event contents](https://docs.aws.amazon.com/ses/latest/dg/event-publishing-retrieving-sns-contents.html) | Hosted tag echo, event delivery after response loss and eventual delivery guarantees. | Callback authentication | SNS documents canonical signed fields and SHA-256 signature version 2. Synthetic RSA tests exercise signature, certificate URL, exact topic, the 24-hour window and hard versus transient bounce. Local integration tests exercise atomic MessageId deduplication, 503 and retry after a write failure, and neutral unverified responses. [SNS signature verification](https://docs.aws.amazon.com/sns/latest/dg/sns-verify-signature-of-message.html) · [Notification format](https://docs.aws.amazon.com/sns/latest/dg/http-notification-json.html) | Hosted topic policies, subscription/delivery retries, authoritative certificate provisioning and rotation, and the configured retry policy within the 24-hour window. |
| MIME and unsubscribe | SESv2 Simple content supports text/HTML alternatives and custom headers. The adapter request includes both RFC 8058 headers and the application endpoint. [Message](https://docs.aws.amazon.com/ses/latest/APIReference-V2/API_Message.html) · [RFC 8058](https://www.rfc-editor.org/rfc/rfc8058.html) | Received MIME, DKIM coverage of both unsubscribe headers and mailbox-provider behavior. |
| Quota and tracking | SES documents per-Region send quotas and selecting events in a configuration set. The app records no opens or clicks. [Sending quotas](https://docs.aws.amazon.com/ses/latest/dg/manage-sending-quotas.html) · [Event publishing](https://docs.aws.amazon.com/ses/latest/dg/monitor-using-event-publishing.html) | Provisioned quota, throttling, production access, tracking settings, reputation alerts and operational response. |
