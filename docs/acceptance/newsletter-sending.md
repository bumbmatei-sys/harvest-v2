# Newsletter campaign server acceptance

This slice adds the campaign editor data model, synthetic sending, and aggregate analytics. Production routes are hard-off before authentication. The delivery worker and callback are off by default and accept only the fake provider in non-production. There is no installed schedule. All five HC-02 gates remain **UNAPPROVED**.

## Screen API

Owner and admin only. The base path is `/api/workspaces/[tenantId]/newsletter`. Reads and estimates return private, no-store JSON. Collections use the immutable UUID `after` cursor and a `limit` of 1–100, default 50. Mutations use the app's existing origin check. An inaccessible ministry or record returns a neutral 404. Conflicts carry a fixed code.

| Method and path | Contract |
| --- | --- |
| GET / POST `campaigns` | List drafts and dispatch state, or create a draft. Draft input includes name, subject, optional preheader, sender and reply-to IDs, selection, and exactly one of content, template ID or starter ID. |
| GET / PATCH `campaigns/:id` | Read the current revision. PATCH takes draft input and the current campaign version and creates a revision. Editing a reviewed draft requires a new review. A finalized revision is frozen. |
| POST `campaigns/:id/review` | Takes `{version, dispatch}`. Returns sender and reply-to, selection pins, estimate, HTML and plain-text preview, headers, and a one-use token with the new version. |
| POST `campaigns/:id/send` or `campaigns/:id/schedule` | Takes `{version, token, dispatch}`. Send uses `{mode:"now"}`. Schedule uses `{mode:"schedule", schedule:{at,timezone}}`, where `at` includes seconds and the local UTC offset, and `timezone` is an IANA zone. The offset distinguishes fall-back instants. Nonexistent spring-forward times are rejected. |
| POST `campaigns/:id/cancel` / `duplicate` / `send-test` | Cancel takes `{version}`. Duplicate takes `{name}` and creates a fresh draft. Send-test uses the verified session user's own address transiently and a fake delivery sink. |
| GET / POST `templates` and GET / PATCH / DELETE `templates/:id` | List includes built-in starters. Create takes name and content, edit also takes version, and delete archives with `{version}`. Campaign creation copies the chosen layout. |
| POST `recipient-estimate` | Takes `{listIds, segmentIds?}`. Returns selected and eligible estimates and fixed reason counts. Segments filter lists in their own audience. Only existing list memberships enter the selection. The selection cap is 5,000 memberships across up to 20 lists and 20 segments. |
| GET / POST `sender-identities` and PATCH `sender-identities/:id` | GET includes domain and SPF, DKIM, DMARC, and ownership metadata. POST takes `{address}`. PATCH takes `{version, enabled}`. Fake verification is confined to the synthetic `example.test` domain namespace. |
| GET `campaigns/:id/delivery-status`, `analytics`, and `analytics/:id` | Reports UTC cohorts by selection day. Query parameters `from` and `until` are inclusive and exclusive UTC dates, with a maximum span of 90 days. No individual outcomes are returned. |

The preview uses the same renderer as dispatch, with a fallback name and a non-authorizing unsubscribe URL. Deliveries substitute the current approved variable values and a recipient-bound NL-02 URL. The body supports the constrained rich-text document, a verified HTTPS button, a scanned ready public image from the same ministry, a divider, spacing, and the mandatory unsubscribe footer. Subject and preheader are authored fields. Footer and header values use the NL-02 signed token and RFC 8058 list scope. GET is read-only.

## Delivery and privacy

Dispatch binds the reviewed sender, selection versions, exact preview, eligible cohort, and schedule. At most one delivery per subscriber and revision is queued, with its immutable delivery UUID as its idempotency key. A list-only restriction applies to that list. A subscriber must have a still-eligible reviewed list and current newsletter email consent. Active lists are never added after review.

The worker checks campaign state, frozen revision, pins, identities, subscriber and list state, and the canonical consent decision inside a short authorization transaction. The worker uses the existing NL-01 SQL equivalent of `mayContact` under the canonical contact-then-subscriber lock order. SQL returns the address only to the live worker call. The fake submission runs after the transaction commits. Withdrawal, erasure, merge, cancellation, and disablement that commit before the authorization check win. There is an in-flight gap after that check. An accepted remote message cannot be recalled.

A lost lease after authorization leaves an unknown outcome. The worker checks status by the same key, never submits again for an ambiguous attempt, and stops polling after 24 hours while retaining an unknown status for review. No SMTP or provider HTTP transport is present. The fake status store lives only for the lifetime of its provider instance. The operator command runs one batch using `WORKER_DATABASE_URL`, `HARVEST_NEWSLETTER_TOKEN_KEY` and an explicit non-production `HARVEST_NEWSLETTER_WORKER_ENABLED=1`. The optional fake callback also requires `HARVEST_NEWSLETTER_CALLBACK_ENABLED=1` and an injected `HARVEST_NEWSLETTER_CALLBACK_KEY`. Worker grants are installed if the separately provisioned `harvest_worker` role already exists. Databases without the role can apply the migration and the worker stays unavailable.

The callback validates timestamp and signature before opening the worker connection. It accepts at most 8 KiB and persists only the delivery reference and fixed outcome timestamps. Evidence can arrive out of order without losing already recorded outcomes. Hard bounces and complaints trigger sticky global suppression. An ordinary callback cannot grant consent, and a list unsubscribe cannot undo suppression. Erasure detaches subscriber references and the address binding without deleting aggregate counts. After a reviewed CRM merge, pending source work is discarded on authorization, and an already attempted source blocks duplicate target work for that revision. A late bounce or complaint follows the canonical target.

Analytics count distinct delivery rows. The denominators are selected recipients for attempts, attempted recipients for provider acceptance, and accepted recipients for delivery. An attempt is recorded at the final authorization boundary. Reported outcomes are evidence flags and can overlap, for example delivery followed by complaint. Missing provider evidence is pending or unavailable. Any nonempty cohort of fewer than five is suppressed. Where a day is suppressed the range total is suppressed too. Reports exclude inboxes, reply threads, engagement profiles, opens, clicks and tracking pixels. Replies use the configured reply-to address. Tracking requires a separate policy decision.

## Verification and founder decisions

Local tests use synthetic contacts, the fake provider and embedded PostgreSQL. Full-run counts are recorded in the draft PR. Hosted Neon, real provider calls, mailbox authentication, monitoring and production deployment are unverified.

Before a separate activation review, the founder needs to confirm whether the selected provider can close the callback, receipt and MIME/header gaps or whether to revisit the provider contract. The founder also needs to specify the sending domain, sender and reply-to ownership, a notice and retention policy, and operating limits. No existing provider for authentication, community mail or Office mail is used for newsletter delivery.
