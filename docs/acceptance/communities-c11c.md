# Communities C11c private messages server

Migration **`0058_community_dm`** follows 0057 with journal timestamp `1795400000006`. The server slice follows the [C11 design](../superpowers/specs/2026-11-17-communities-c11-chat-design.md). The gated endpoints use the existing Communities authentication and origin checks and return 404 before authentication in production.

- Private conversations, participant preferences, messages and community-scoped blocks use participant and blocker policies. New tables force RLS. The app has zero table privileges on evidence.
- Sending is find-or-create by pair. Current owner/admin rank controls staff engagement. A member can reply to the current engaging host while policy is off or while muted. Both directions refuse a blocked pair with the same generic outcome. Send and edit windows, hourly and daily conversation caps, and the unanswered cap run inside the database.
- Polling uses committed conversation revisions and exact page cursors. Private participant rows carry DM revisions. Shared membership revisions and tenant audit reads expose no DM activity. The rail tracks the caller’s visible threads and actions. The list provides a continuation cursor. Grouped DM notifications hold no message text, respect both mute controls and leave email delivery off.
- A report stores the target plus at most five visible predecessors. A non-party owner/admin can open it, identifying the reporter, or decide it. Moderators get reason and note through the report queue. Review routing includes ministry owner/admin capability. A report with no eligible reviewer is marked for escalation. Every evidence open is audited. The audited projection identifies the reported member and message. An authorized non-party reviewer can attach a warning, mute or ban to an action decision, including an eligible ministry owner/admin without a community membership. Report reminders use the recipient-scoped notification path.
- The worker can purge expired deletions, empty hidden conversations and expired snapshots. It sends in-app reviewer reminders at 14 and 45 days and closes open reports at 90 days. Decided evidence expires at 180 days. Evidence on an expired report expires 30 days after closure. Worker output is counts only.
- A block is not observable to the blocked person: the conversation list (including `canSend`), the rail token and the new-message recipient search report only the non-block part of the send rules, so their view is identical before and after the block and only sending returns the generic `not_available`. Blocking a person who is not an active member returns the same `ok` as blocking a member and stores nothing. Covered by the single-outcome integration test.

## Validation

Local lint, typecheck, build and 1,120 unit tests passed. A focused author run passed 50 tests across the DM, channel chat and worker-role integration suites. The DM suite uses a restricted migration owner and exercises two ministries, participant reads, raw evidence denial through `withTenant`, staff demotion and re-engagement, idempotency, marks and mute, snapshots, expiry and worker grants. The ownership-transfer and invitation suites passed another 26 tests after the fixture was updated to move nested 0058 functions together.
