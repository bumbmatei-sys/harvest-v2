# Office server acceptance

Office exposes personal Mail, Calendar and Files to ministry owners and admins. One admin can have one active connection per area in each ministry. Only the signed-in person who completed the connection can read or use it. A ministry owner has the same personal boundary as an admin. This server slice supplies the API for Operations and Settings → You → Connections. The screens and sidebar changes belong to the separate screens and shell work.

## API handoff

Base path `/api/workspaces/{tenantId}/office`. `GET` returns `{ notice: { key, version }, connections }`. Each connection returns the Harvest `id`, area `kind`, internal identity `platform`, `health`, numerical `grants`, `noticeVersion` and per-operation `capabilities`. Use the catalogue key `Office.personalConnectionNotice` at connection start. Display the localized notice before sending the current version. The grant codes are Mail = 1, Calendar = 2, Files = 4, and 0 = no grant. Connection health is `healthy`, `unavailable` or `reconnect_needed`.

`POST` accepts same-origin JSON `{ action, connectionId?, input }`. Use the Harvest connection ID throughout. The response is `{ state: "available", data }` for successful operations. Lists carry `items` and, for paginated results, `nextCursor`. Follow a non-null cursor even when the page is empty. `partial: true` means the returned page had degraded coverage or provider-side filtering constraints. `unavailable`, `reconnect_needed`, `temporarily_unavailable` and `disabled` have no `data`. Authentication failure is 401. Missing and foreign records use the same 404. Invalid operation input uses 400 and stale edits and reviews use 409. The gate answers 404 before session work in production. All responses use private, no-store caching.

| Action | Input and result |
| --- | --- |
| `startConnect` | `{ kind, platform, noticeVersion }` with optional `connectionId` for reconnect. Identity keys are `google` and `microsoft`. Returns `{ state: "pending", attemptId, url, expiresAt }`. The synthetic provider returns `url: null`. Open a hosted authorization URL directly in a new browser tab and keep it out of persisted client state. |
| `finishConnect` | `{ attemptId }`. Poll the same signed-in account about every 2–5 seconds while pending. A verified handoff returns `{ state: "connected", connection }`. An expired or failed attempt returns `failed`. The development fake seeds a sample in each connected area. A successful response consumes the attempt. Refresh the connection list after an ambiguous response. |
| `health`, `disconnect` | `{}` and `connectionId`. Health refreshes the grants and reconnect state. Successful disconnect returns `disconnected` and removes the connection and its local markers and links. Retry a transient disconnect failure. |
| `threads`, `thread` | `{ cursor?, limit?, folderRef?, search? }` and `{ threadRef }`. Search goes to the provider using its native syntax. Thread details return `ref`, `subject` and `messages` containing plain-text `body`, `from` and `to`. Each thread carries its Harvest `marker`. Render mail as text with remote images off. |
| `folders`, `labels` | `{}`. Returns named refs. Outlook organizations can block category enumeration and the provider documents an empty result in that case. |
| `drafts`, `draft` | `{ cursor?, limit? }` or `{ draftRef }`. The detail operation returns the current body and version. Gmail list rows may omit bodies. |
| `createDraft`, `updateDraft`, `deleteDraft` | Create uses `{ requestId, content }`. Update uses `{ draftRef, version, content }`. Delete uses `{ draftRef }` and applies to the selected draft at the time of the call. `content` is `{ to, subject, body }`. Drafts live in the connected mailbox. |
| `marker` | `{ threadRef, read?, starred?, contactId? }`. Omit fields to leave them alone. Explicit `contactId: null` unlinks. Read and starred are Harvest-only. Linking requires a visible, existing CRM contact. |
| `reviewMail`, `sendMail` | Both surface `disabled` in HTTP. Tests inject the in-memory sender. Review takes `{ content }` and returns a five-minute, single-use review token. Send takes `{ content, reviewToken }`. Optional `content.messageRef` identifies a reply. The token binds actor, ministry, connection, recipient list, subject, body and reply target. A new review is required after expiry or content changes. |
| `calendars`, `events`, `event` | `{}`, `{ calendarRef?, start, end, cursor?, limit? }` or `{ eventRef, calendarRef? }`. Ranges use ISO datetimes, at most 93 days. Events return attendees and a meeting URL and kind when supplied. All-day event dates retain the provider's YYYY-MM-DD form. |
| `freeBusy`, `availability` | Free-busy uses `{ calendarRef?, start, end }` and returns busy blocks. Availability uses `{ start, end, durationMinutes }` and returns candidate slots. Both are scoped to the selected personal connection. |
| `createEvent`, `updateEvent`, `deleteEvent` | All surface `disabled` in HTTP. Create takes `{ calendarRef?, requestId, event }`, update `{ eventRef, calendarRef?, event }`, delete `{ eventRef, calendarRef? }`. An event write has `{ title, start, end, description?, attendees, meeting? }`. |
| `drives`, `files`, `file` | `{}`, `{ folderRef?, search?, cursor?, limit? }` or `{ fileRef }`. Omit the folder ref for the connected root. Files include `kind`, name, parent ref, MIME type and size where reported. Synthetic drive enumeration is available. |
| `preview`, `downloadLink`, `picker` | File links take `{ fileRef }`. Preview returns the provider web URL under its existing permissions when supplied. A standalone private download link is unverified and unavailable on the vendor adapter. The hosted picker returns `{ mode: "hosted", url, expiresAt }` on supported accounts. The fake returns `{ mode: "inline" }`. For accounts without a hosted picker, select from the files list. Reload the list after an external pick. |
| `fileLink`, `eventLink`, `contactReferences`, `removeReference` | Link an existing CRM contact using `{ contactId, fileRef }` or `{ contactId, eventRef, calendarRef? }`. List with `{ contactId }` and unlink with `{ contactId, itemRef }`. Linking looks up the selected item live under the owner connection. File links keep its ID and name. Event links keep its ID and start/end. All-day dates use UTC date markers for these local references. |

## Access and data boundary

The Office adapter accepts the same injected API credential as Social. Office receives no platform token and uses no direct platform OAuth client. An isolated provider profile requests only the selected area, and the OAuth completion is verified against a server-owned handoff, profile, platform and existing account on reconnect. Provider retention settings can affect Social uploads under the shared key, so the adapter leaves them to the provider account's configured policy. Hosted handoff and reconnect semantics, actual grants and revocation, provider retention and live read behavior, provider-side profile cleanup and limits, and calendar create idempotency require sandbox verification. The PR uses no real credentials or provider calls. [Google OAuth](https://docs.zernio.com/platforms/google/connect) · [Microsoft OAuth](https://docs.zernio.com/platforms/microsoft/connect) · [Provider retention controls](https://docs.zernio.com/security/zero-content-retention)

Harvest stores personal connection IDs, provider references, health, grant codes, the privacy notice version and explicitly selected local metadata. Mail text, addresses, subjects and drafts are transient, as are calendar content and file links. The adapter returns plain mail text and omits rich HTML. An HTML-only message sets `bodyUnavailable`. No Office webhook endpoint or body cache is present. Office neither creates CRM contacts nor records contact consent. Audits carry only actor, ministry and target IDs, action, outcome and timestamp. Row policies filter connection records, attempts, markers, linked references and Office audit records to the personal owner.

Contact erasure deletes Office file and calendar references, including stored file names and event times, and clears the contact ID from thread markers while preserving their read and starred flags. Contact merge drops the source's Office links through the same erasure path. The target's existing links are preserved.

Migration `0075_office_server` extends the original Office table from `0053`. It removes obsolete per-connection credential envelopes and keeps legacy records as reconnect-needed with zero grants. The new membership FK governs new writes. Any legacy rows whose membership had already been removed stay invisible through RLS. The migration uses FORCE RLS and ministry-qualified FKs. Its snapshot follows CRM migration `0074`, which landed in PR #183.

`OFFICE_INTEGRATION_ENABLED`, `OFFICE_LIVE_NETWORK`, `OFFICE_MAIL_SEND_ENABLED` and `OFFICE_CALENDAR_WRITE_ENABLED` are literal false. All five HC-02 gates are UNAPPROVED. No production migration or deployment was performed.


## Pre-activation decisions

- Connect start and finish hold a transaction and an advisory lock across provider requests. Each request can take up to eight seconds. Decide how to handle lock duration and database connection use under live traffic.
- Removing a ministry member cascades their local Office connections. Activation needs a provider-side revocation and cleanup path for accounts left linked after removal.
- Mail review tokens are held in per-instance memory. Decide how review and send will work across instance changes and restarts.
