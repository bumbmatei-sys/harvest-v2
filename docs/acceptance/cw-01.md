Baseline: `c30abb5` / PR #19. Scope: [Campaign Wizard PRD, Founder decisions and CW-01](../prd/harvest-campaign-wizard.md), [ADR 0003](../decisions/0003-rls-tenancy.md), and Campaigns ownership in [ADR 0011](../decisions/0011-harvest-connect.md).

## Done checklist

- [x] `campaigns` belongs to the parent workspace via `tenant_id`; composite `(tenant_id, id)` PK. No additional workspace is created.
- [x] Five PRD types, creator as owner, draft default, optional description/mission, country/city-region, date range, time zone and structure; timestamps and nullable archive marker. Text checks follow existing Drizzle conventions. `active` is reserved; creation is draft-only and no activation/update/delete API or SQL grant exists.
- [x] `0021_campaigns.sql` adds schema, indexes, FORCE RLS, membership-gated SELECT/INSERT policies and runtime grants. No public role policy. Fresh migration, replay and upgrade from `0017` verified locally without changing existing workspace/contact data.
- [x] Authenticated create/list/get under `/api/workspaces/:tenantId/campaigns`. Existing verified-session, origin and locked `withTenant` checks. Foreign workspace access denies (403); foreign/missing campaign IDs in an accessible workspace return 404. Reads use `private, no-store`.
- [x] Create requires an opaque `Idempotency-Key` (1–200 letters/digits/`.`/`_`/`:`/`-`). Tenant-unique key plus canonical request/creator fingerprint follows the outbox conflict pattern. Same normalized request returns the original campaign; changed payload or creator gives 409. Keys/fingerprints stay internal. One minimal `campaign.create` audit row is atomic with creation, including concurrent retries.
- [x] Private list/empty state at `/workspaces/:tenantId/campaigns` and dashboard shell at `/workspaces/:tenantId/campaigns/:campaignId`. Existing shadcn UI and one workspace navigation entry; no create UI or wizard. Pagination is 20 rows. Desktop/mobile gutters verified at 24px/16px, with no page overflow.
- [x] Two-tenant service, raw SQL and HTTP isolation; member/non-member/viewer checks; owner spoofing and activation denial; same-backend context reset after commit/rollback; concurrent retries; audit failure rollback; input/date/time-zone validation.
- [x] Chromium smoke: signed-out denial, empty list → API create → list → dashboard, retry/conflict/origin checks, two-way isolation and viewer denial. Dashboard axe WCAG A/AA check: zero violations. No browser page errors. The dev server emits a React script-tag warning while rendering the intentional inaccessible-page check.
- [x] Founder decisions respected: no donation/payment implementation, department boards or CRM task extensions, or AI setup. No CW-02–CW-12, HC-* implementation, CRM-05/06, switcher, duplicate CRM/finance/calendar, or new dependencies.

`0018`–`0020` are reserved for CRM-05; journal/snapshot numbering intentionally skips to `0021` without placeholder migrations. The journal test still checks increasing indices/timestamps and a single snapshot chain. **migration 0021 may need renumber on rebase** if CRM-05/HC-04 land conflicting numbers.
