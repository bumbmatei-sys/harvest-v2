# HC-03 — Campaign QR link admin, publish / disable / rotate, short URL

Date: 2026-11-07. Baseline: `main` at `ec7ab892a79ae527c2c9bb4e3ff29202bf0e7c7c` (HC-02 #28 merged; HC-01, HC-04, CW-01, CRM-01–08 present; last migration `0026_hc02_connect_intake`). Migration: **`0027_hc03_connect_links`** (0026 is not edited or renumbered). Scope sources: [slice plan](../prd/harvest-connect-slices.md) HC-03 row; [Connect PRD](../prd/harvest-connect-qr-to-discipleship.md) §§4–5, 9–12, 15–19; [ADR 0011](../decisions/0011-harvest-connect.md); [threat model](../security/harvest-connect-threat-model.md); [HC-02 record](hc-02.md) §§2, 5, 7–8; [HC-04 contract](../decisions/hc-04-public-presentation.md).

HC-03 lets an authorized organizer create, preview, download, publish, pause, rotate and archive a campaign's public QR code and short URL. It connects HC-04's public landing to a constrained database resolver. **It collects nothing from a scan.** It adds no response form, intake path, CRM association, invitation, delivery, job, outbox event, analytics, Communities or Forms builder.

## 1. Rules (explained before coding, then implemented)

### Authorization

| Action | Who | Where enforced |
| --- | --- | --- |
| See a campaign's links (status, short URL) | Any workspace member | 0026 member read policy (unchanged); `campaigns:read` |
| Create a draft link, preview it, project it, download PNG/SVG/PDF | Owner, admin or member (the campaign organizers) | 0026 draft-only insert policy (unchanged); `campaigns:write` |
| Publish, pause, publish again, rotate, archive | **Owner or admin only** | New `connect:publish` permission **and** the `connect_link_transition` definer, which re-checks live owner/admin membership with `FOR SHARE` on every call |

Publishing reuses the repository's existing publishing contract: Forms versions and privacy notices already publish as owner/admin. It is deliberately not blanket member access. `harvest_app` still has **no UPDATE or DELETE** on links, so status, codes and expiry change only through the definer. A demoted or removed publisher is refused on their next request, even if their session is still open (tested).

### Lifecycle

`draft → published ⇄ disabled (paused) → archived`. Archived is terminal. Expiry is a time on a published link: once it passes, the link behaves like a paused one until it is republished with a later expiry or none.

| Transition | Preconditions (all re-checked by the definer and by the row guard, even for owner DML) |
| --- | --- |
| Publish (from draft or paused; or change the expiry of a live link) | Campaign exists in the same workspace and is not archived. Any attached form version is `published` (not draft or retired). Expiry is empty or in the future. Same-state, same-expiry requests return `unchanged` |
| Pause | Only from published; idempotent |
| Rotate | Any non-archived state. The caller must name the code it is looking at (`expectedCode`), so a concurrent rotation turns the second request into `stale` (409). Tested with two connections: exactly one wins |
| Archive | Any state. Retires every code. Later actions return `link_archived` (409) |

**Decision recorded: active-campaign requirement.** Matei answered the HC-03 question on 2026-11-07: *"No — link publish is the activation."* An owner/admin publishing a link is itself the explicit, audited public activation of that one source. The campaign must still exist and not be archived. CW-01 `active` status is **not** required, because nothing in the repository can activate a campaign yet. If campaign activation later becomes a gate, it is one predicate in `connect_link_transition` and the row guard.

**Form version validity.** A draft link may reference a draft or published form version of its own workspace; retired versions are refused. The composite FK refuses another workspace's version. Publishing requires `published`. If the version is retired after publishing, the link keeps showing the welcome page and resources, and the admin card says so. No link accepts a submission in HC-03 regardless, because HC-05 owns intake. 0027 also extends 0026's response guard so that an expired link would refuse a response, closing that gap before HC-05.

### Codes, rotation history and old-code behavior

- **QR code:** a 128-bit random `public_code` (32 hex) in `/c/{code}`.
- **Short URL:** a 60-bit random Crockford base32 `short_code`, displayed as `/s/XXXX-XXXX-XXXX`.
  - It contains no ambiguous `I L O U`.
  - Typed input is normalised: case-insensitive, hyphens and spaces ignored, `O→0` and `I/L→1`.
- **Both codes are generated by the database** from `gen_random_uuid()`'s strong random source, using only its random nibbles. A caller-supplied value is overwritten at insert, following the HC-02 server-computed notice hash precedent.
- URLs carry only the opaque code. They contain no tenant, campaign, person, form or secret, and no query string.
- **Registry:** `campaign_response_link_codes` records every code ever issued, current and retired.
  - Its global unique index means a code is never reissued, even across workspaces.
  - Rows are append-only. A row can only retire, once.
  - Only the link definers write it. Members can read their own workspace's history (the "Rotated N times" count).
- **Old codes fail safely.** A rotated-away, archived, paused, draft, expired or unknown code gets the **same** response: HTTP 404, the general "This page isn't available" page and a link to the free starter resources. That keeps those states indistinguishable to a guesser.
- Old codes are **never redirected** to the new code. Rotating after a leak must cut the old code off.

### Variants (reconciled without new scope)

| PRD §5.1 variant | HC-03 |
| --- | --- |
| Campaign | Required, via the composite FK (0026) |
| Language | `locale`. Only `en` exists in the catalogue (HC-04), so the picker offers English. The resolver passes stored locales through the same `resolveFromLocales` path |

## 2. Public resolver and HC-04 integration

`resolve_connect_link(kind, code)` is a SECURITY DEFINER function, granted to `harvest_app` and read-only.

- It validates the code format before any lookup.
- It derives the tenant **from the code**. A caller's `app.tenant_id`, user or forged context is ignored (tested with another workspace's context).
- It returns exactly `(locale, public_title)`, and only for a published, unexpired link whose campaign is not archived.
- It never touches responses, contact methods, consents, CRM, memberships, jobs or the outbox.

| Exposed publicly | Never exposed |
| --- | --- |
| Public title (if set); locale; the fixed starter resource ids; `acceptsResponses: false` | Tenant/workspace, campaign, link and form ids; internal campaign name; internal label; status of a non-published link; pending responses; contact methods; consent evidence; anything about people |

**How the definer reads across tenants without BYPASSRLS.** The definer's owner obeys FORCE RLS. It gets only narrowly scoped policies:

- a SELECT policy on links matching `public_code`/`short_code` to `app.connect_resolve_code`;
- SELECT policies on `campaigns` and `form_versions` matching `app.connect_resolve_tenant`.

The resolver sets those two settings internally and clears them before returning (tested). No `harvest_app` policy reads them, so setting them from the application reads nothing (tested). The lifecycle definer uses tenant-scoped owner policies on links and the registry, plus a read-only campaign policy.

**Caching and revocation.** `/c/[publicCode]` and the new `/s/[shortCode]` are `force-dynamic`: no static, ISR or full-route caching.

- Responses are `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate` (asserted in the browser test).
- React `cache()` dedupes the page and its metadata only within one request.
- The service worker still caches static assets only (HC-04).
- A pause, expiry, rotation or archive therefore applies to the **next request** after commit; the browser test checks this immediately after each change.
- The only residual window is a request already being rendered at commit time.
- A database error resolves to "unavailable", so guests still reach `/resources/start`, which needs no database.

HC-04's static preview code `9f4c…` still resolves first, unchanged, and its tests still pass. The landing is now a shared `LandingContent` used by `/c`, `/s` and the admin preview. The low-bandwidth path is unchanged: server-rendered, no prefetch, no form, input, tracker, cookie or third-party request.

## 3. Admin UI

**Where.** `/workspaces/{tenant}/campaigns/{campaign}/connect`. The entry point is a card on the campaign dashboard.

**Components.** Existing shadcn primitives only: Card, Badge, Button, Dialog, AlertDialog, DropdownMenu, Field, Input, NativeSelect, Alert, Empty. Full-width shell with 24/16px gutters. Copy comes from the catalogue, with no vendor names and existing "workspace" wording.

**Eden references.** The local reference screens shaped:
- a "Before you publish" checklist (`26-editor-publish-checklist.jpg`);
- share rows with a monospace short link and copy action (`28-editor-publish-share-links.jpg`).

What a card shows:
- **Header:** the internal name and a status badge (Draft / Live / Paused / Expired / Archived), with plain-language consequences.
- **QR and short URL:** an inline-SVG QR from the same renderer as the downloads, the short URL with Copy link, and the public title.
- **Details:** form state, language, expiry, and the rotation count.

Actions:
- **Organizers:** Preview, Present, and Download (PNG / SVG / PDF, each Standard or Brand frame).
- **Owners/admins:** Publish (checklist plus optional expiry), Pause, Publish again, Rotate code and Archive, with confirmations that explain the effect on printed codes.
- Members see a note that only owners and admins publish.

**Preview** (test mode, `/connect/{link}/preview`) renders the public page as this link would, inside the signed-in app. It works for drafts and paused links, and is noindex, never public, and records nothing.

**Present** (projection, `/connect/{link}/present`) covers the shell with the code as large as the screen allows, black on white in either theme. It shows the public title, "Scan to open" and the short URL in large monospace. A clear warning appears when the link is not live.

**Exports** (`GET …/links/{link}/export?format=png|svg|pdf&palette=standard|brand`; organizers only, `private, no-store`, `nosniff`, safe `Content-Disposition`):

| Format | Content |
| --- | --- |
| PNG | 8-bit RGB, 24 px per module, 4-module quiet zone, no metadata chunks |
| SVG | One path, escaped `<title>`, nothing executable |
| PDF | One A4 page of vector rectangles about 14 cm wide, plus the caption and the short URL. Standard Type 1 fonts with ASCII-only text, no images, scripts, links or producer metadata |

**Error correction and palettes.** Error correction is Q (about 25% damage tolerance). The Standard palette is black on white. Brand uses the workspace theme's dark brand ink for modules (contrast ≥ 7:1 is enforced, falling back to black otherwise). It puts the brand colour only in an outer frame beyond the white quiet zone, so it cannot affect scanning. Archived links cannot be exported.
