# CRM-01 / CRM-02 acceptance record: People and Companies

Date: 2026-11-05. Scope: PRD v2.5 §5A.4 CRM-01 (schema, keys, scope constraints, RLS, audit) and CRM-02 (tables, record pages, inline editing, search and paging), companion PRD §5. Design: [ADR 0007](../decisions/0007-crm-companies-and-links.md). Reference study: [Twenty and v1 notes](../research/twenty-crm-reference.md).

## What a user can do

- **People** (`/workspaces/:tenantId/crm/people`): search by name, email, phone, handle or company name. Filter by any company / no company / one named company (server-searched picker), by email presence, and by effective email-marketing state (subscribed, unsubscribed, no decision). Sort by name, created or updated date. Pages hold 20 rows. All view state lives in the URL. Each row shows the primary company with "+N" for others, email, phone, marketing state and added date.
- **Person record**: edit the name inline in the page title, and email, phone, social handle and notes inline in their fields. Link existing companies or create one from the picker, set a role, make a company primary, and unlink. See same-name suggestions (never merged), the consent ledger tab (unchanged behaviour), and an activity timeline built from real audit events. Owners and admins can erase the person.
- **Companies** (`/workspaces/:tenantId/crm/companies`): search by name or domain; filter by has people / no people and has domain / no domain; sort by name, date or people count. The count links to the People view filtered to that company. Creating a company normalizes a pasted URL to its domain. A duplicate domain is refused with a link to the existing company.
- **Company record**: edit the name, domain and description inline. Link existing people, or create a new person linked with a role. See the people table, same-name suggestions and an activity timeline (company edits plus link and unlink events).
- **States**: empty, no results, invalid view (default view shown with a notice), loading skeletons for lists and records, inline validation, duplicate-identifier and stale-version errors, network failure, view-only, not found, and workspace access denied.
- The old `/workspaces/:tenantId/contacts[/:id]` routes redirect to People and keep their query string. The sidebar has a CRM group (People, Companies) and a Workspace group (Files).

## Security and data rules verified

- Both new tables force RLS. Without tenant context the runtime role sees no rows.
- Composite tenant FKs stop a link from joining a contact and a company in different tenants, even for the table owner. RLS `WITH CHECK` blocks writing rows for another tenant.
- Two tenants were tested **in both directions**:
  - **Services and direct SQL** (`tests/integration/crm.test.ts`): forged workspace hints, foreign IDs in get, patch, link, create-with-company and activity, filters by a foreign company ID, unqualified selects and updates, and foreign-tenant inserts.
  - **HTTP API** (`tests/e2e/crm.spec.ts`): owner A against B's IDs and URLs, and B (a viewer in A) trying to pull A's records into B.
- Permissions: viewers read only. Every CRM mutation returns 403 for a viewer, through the service and the API. Unknown roles fail closed. Origin checks apply to every mutation.
- Optimistic versions reject stale edits (409, nothing changed). No-op patches write no audit row.
- Normalized identifiers are unique per tenant. A duplicate rolls back the whole patch, so nothing changes and nothing merges. Company domains are unique per tenant; names never block a save.
- Audit metadata carries field names and IDs, never personal values (asserted). Provenance (`created_by`) is bound to the verified transaction user by trigger. Link identity is immutable, and the runtime role has no company DELETE grant.
- Erasure removes the person's links before re-keying and scrubs their link history from company activity. The company survives, and an erased tombstone cannot be linked again, even by direct SQL.
- The effective marketing state in the list (badge and filter) matches the record page, including a backdated grant that must not override a withdrawal.

## Defects found and fixed while testing

1. **Zod 4 `.default()` short-circuited the domain transform**, so an omitted domain reached SQL as `""`. The `company_domain_format` CHECK rejected it. Fixed with `z.string().default("").pipe(domainField)`.
2. **The People-list marketing badge was wrong**: Drizzle renders single-table select columns unqualified, so `w.contact_id = "id"` bound to the consent row's own id. The filter was correct and the badge said "No decision". The outer reference is now explicit. A test asserts the badge, the filter and the record page agree.
3. **Domain normalization** accepted `mailto:x@example.org` as credentials plus a host. Now only http(s) and bare hosts are accepted; credentials are rejected; `host:port` still works.
4. **A quick second view change while a navigation was in flight** rebuilt the URL from stale params and resurrected old filters. The view bar now builds on the in-flight query.
5. **Accessibility** (axe): the inactive tab text failed contrast on Harvest surfaces (`text-foreground/60` changed to `text-muted-foreground`); company link rows lacked `listitem`; a disabled pagination `<a>` had no href; the empty-field accessible name did not match its visible text; and the editable title changed the heading's accessible name.
6. **The network-failure message** fell through to a generic error because a key was passed where error text was expected.

## Migration notes

- `0011_crm_companies` (generated): creates `companies` and `contact_company_links`. Adds to `contacts` a stored generated `normalized_name` and `version int default 1` (with a CHECK of at least 1), plus indexes on `(tenant_id, normalized_name)` and `(tenant_id, created_at, id)`. Adding a stored generated column rewrites `contacts` once.
- `0012_crm_policies_erasure` (hand-written): forced RLS and policies, column-scoped grants, the erasure-owner policy on links, the `guard_company_link` and `guard_company_provenance` triggers, and `CREATE OR REPLACE erase_contact` (adds link deletion; otherwise identical to 0008).
- Additive, and idempotent under the harness's double-apply. `tests/integration/crm-upgrade.test.ts` seeds a 0010 database with a contact, an identifier and consent, then upgrades, patches, links and erases it. Existing rows get `version = 1`.
- Rollback before deploy: drop both tables, drop the two new `contacts` columns and indexes, and restore `erase_contact` from 0008. No production data exists.

## Deviations (documented)

- **Routes**: CRM routes are prefixed with `/workspaces/:tenantId` (ADR 0003/0004); the API keeps `/api/workspaces/:tenantId/...` (ADR 0007).
- **Escape** cancels an inline edit; Twenty persists on Escape.
- **People can belong to several companies**, one of them primary (Twenty has a single `companyId`).
- **shadcn Command** was copied from the MIT `shadcn-ui/ui` repository at a pinned commit, because `ui.shadcn.com` is blocked by this environment's egress policy and `npx shadcn add` could not reach the registry (see `docs/ui-sources.md`).

## Known limitations

- One email, phone and handle per person (PR 01b constraint); no multi-identifier editing yet.
- No merge, bulk edit, CSV import/export, saved views, column configuration, grouping or keyboard grid navigation; table cells are not editable in place (editing is on record pages).
- Companies cannot be archived or deleted, and have no owner, address or size fields.
- Activity shows CRM audit events only (create, update, link, consent); no tasks, notes or timeline events from other modules exist yet. Actors who left the workspace are shown as "A former member".
- Same-name suggestions compare exact normalized names only; there is no fuzzy matching.
- No previous/next navigation between records in a view.
- No CRM outbox events are emitted: there is no consumer yet, and the durable queue would dead-letter unknown kinds. Activity uses the audit ledger.
- The `error.tsx` boundary was not forced in the browser. Request-level failures (network failure, 409 conflicts, validation) were exercised.
- Neon dev-branch verification and the CI PostgreSQL 17 jobs were not run in this session.

## Layout revision (2026-11-05, same PR)

Founder feedback: the record pages read like a narrow centred document. The layout was corrected at the shared shell level. The data model, permissions and workflows are unchanged.

- **Shell** (`src/components/app-shell.tsx`): removed the `mx-auto max-w-[1040px]` column and its 40–56px vertical padding. `[data-shell-content]` is now `w-full max-w-none`, with 16px gutters (24px from `lg`) and a 4px top gap. The breadcrumb header uses the same gutters, so the page aligns under it. Every workspace screen inherits this; ADR 0004 records the supersession.
- **Focused short forms** stay narrow but left-aligned: Profile and Appearance (`max-w-xl`), the create-workspace card, and the Files upload form, which now sits beside the file list at `xl`. The workspace cards grid grows to three columns at `xl` and four at `2xl`. Sign-in is outside the shell and unchanged.
- **CRM**: tighter header rhythm, and a shared `RecordHeader`/`RecordBackLink`/`RecordGrid` (`src/components/crm/record-layout.tsx`). The back-link icon sits exactly on the content edge (asserted).
  - **Person record:** profile (Details, Companies) → context (Notes, Marketing) → history (Activity/Consent).
  - **Company record:** profile (Details, Description) → context (People, wider) → history (Activity).
  - **Responsive:** three columns from 1536px; two columns plus a full-width history row from 1024px; stacked on phones.
- **Problems found by inspecting screenshots, then fixed:**
  - The company People table clipped its row-action column at 1920px. Its columns now respond to the card's own width (container queries), not the viewport.
  - Domain and email values wrapped mid-word in narrow columns. Fixes: a narrower field label column; the edit button overlays on fine pointers and stays in flow on touch; and the three-column grid now starts at `2xl` instead of `xl`.
  - Company names on mobile truncated early because the People count column took the spare width.
  - The layout checker gained a sideways-scrolling-table check, which caught the clipped People table automatically.
- **Verification:** lint ✓, typecheck ✓, unit 113 ✓, integration 128 ✓, Playwright **8/8** ✓. The new `layout.spec.ts` covers workspaces, files, appearance and profile at 1920px and 390px in both modes, with axe; the existing pr01b/pr03 shell and axe specs also pass. I inspected the new captures myself: wide People, Companies, person and company in both modes, and mobile list and detail.
