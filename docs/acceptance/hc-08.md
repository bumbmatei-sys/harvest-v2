# HC-08 — Free-account onboarding and profile: acceptance record

Slice contract: *Free identity/profile, purpose preferences, onboarding. Done when an account activates and preferences work while choosing no community.* Design `docs/superpowers/specs/2026-11-11-hc-08-free-account-onboarding-design.md`, plan `docs/superpowers/plans/2026-11-11-hc-08-free-account-onboarding.md`. This is a foundation slice, not the community journey.

## What shipped

- **Data (migration 0034, `0034_user_profiles`):** `public.user_profiles` with one row per account (`user_id` primary key, cascade on account deletion; optional `city_region` of 1–200 characters; `onboarding_completed_at`, `onboarding_skipped_at`, `updated_at`). FORCE row-level security; the runtime role gets SELECT, INSERT and UPDATE only, limited to its own row; no delete right. Every account that exists when the migration runs is backfilled as skipped (before RLS is enabled), so existing accounts are never prompted.
- **Server (`src/server/account-profile.ts`):** read the profile and derive onboarding status (`pending`, `completed`, `skipped`; completed wins), save onboarding, skip, and update the profile without changing status. Strict validation: name 1–100 trimmed, language from the supported list or none, city 1–200 trimmed or none, unknown keys rejected. Display name stays in `users.name`, language in `users.locale`.
- **API:** `PUT /api/account/profile`, `GET /api/account/profile`, `POST /api/account/onboarding` (`save` or `skip`). Session and origin checks as for other account routes; invalid input returns 400.
- **Screens (shared `AccountProfileForm`, `PublicFrame personal`):**
  - `/account/onboarding`: name, language, optional city, and the four path options. Only `Explore later` is selectable; `Find a free community`, `Start a Bible course` and `Find a church` are disabled with a "Coming soon" badge. Nothing about the choice is stored. `Save and continue` and `Skip for now` both go to the welcome page, keeping a safe return path.
  - `/account/profile`: the same fields, saved through the profile endpoint.
  - `/account/welcome`: accounts whose onboarding status is `pending` are redirected to onboarding; once skipped the page shows `Finish setup`. The invitation claim service and its tests are unchanged.
- **Privacy:** no religious-status field, no directory-visibility setting, no consent switches. Withdrawal and response deletion remain on the existing response-rights page. Account pages stay `noindex` with `no-referrer`. Production intake and invitation delivery remain hard-disabled.

## Founder decisions applied (11 Nov)

All four path options shown with three "Coming soon"; account-level preferences only; no directory visibility until HC-09; onboarding once after activation, skippable and reachable later; new `user_profiles` table (approach B).

- Integration `account-profile` (7 tests): backfill marks pre-existing accounts skipped and new accounts pending; save, skip, update; invalid input in the service and the database; a person reads and writes only their own row (including a forged insert for another user); no delete right and cascade on account deletion.
